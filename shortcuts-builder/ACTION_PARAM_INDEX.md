# ACTION_PARAM_INDEX

## Purpose

Quick-reference table of parameters for high-frequency actions. When generating XML, check this table first to confirm required keys, serialization type, and common mistakes, instead of reading all of BEST_PRACTICES.

## Reference Conventions

- **Required** = missing it causes validation failure or import errors
- **Recommended** = import works without it, but omitting it reduces usability
- **Serialization** = the `WFSerializationType` that parameter should use
- **TokenString** = `WFTextTokenString`(with `￼` + `attachmentsByRange`)
- **Attachment** = `WFTextTokenAttachment`(pure variable reference, no wrapping text)
- **Variable wrapper** = `{ Type: "Variable", Variable: { Value: ..., WFSerializationType: "WFTextTokenAttachment" } }`

| Identifier | `is.workflow.actions.text.replace` |
|--------|-------------------------------------|
| OutputName | `Updated Text` |

| Parameter | Required | Type | Description |
|------|------|------|------|
| `UUID` | ✅ | string | |

## Display Parameters vs Data-Flow Parameters Quick Reference

| Parameter category | Serialization | Typical parameters |
|---------|-----------|---------|
| **Display parameters** (user-visible text) | **Must be TokenString** | `WFAlertActionMessage`, `WFAlertActionTitle`, `WFNotificationActionBody`, `WFNotificationActionTitle`, `Text`(ShowResult) |
| **Data-flow parameters** | Attachment allowed | `WFInput`, `WFDate`, `WFVariable`, `WFDictionary`, `WFNote`, `WFFile` |

**Using Attachment for a display parameter → the field shows empty at runtime.** This is one of the most common mistakes.
